# Prepare this close

Apply migration 016 after migrations 001–015. The same API/database-backed behavior runs locally and in Cloudflare containers; there is no second queue or calculation engine.

1. Open a client/month and upload the available evidence. Each upload already owns one durable interpretation/preparation job. Local proposals use explicit labels; configured OpenAI interpretation uses the existing source/citation and confirmation controls.
2. At the top of the close, inspect the listed source documents and confirm **Prepare this close**. The server checks the exact current inventory and records its actor, digest and source/job identities. Repeating the action on the same inventory returns the same run.
3. The run reads each original job's real status. Follow a source link to Work to inspect proposed facts, resolve questions, approve a client request or confirm preparation. Repeated question wording is grouped, but answers are never copied between invoices automatically.
4. Approved replies resume their original jobs. Refreshing the browser or restarting the API does not create new jobs. The view polls every five seconds and reports errors instead of treating a failed read as success.
5. New or replaced source documents produce **scope changed**. Review the current list to record a new scope; earlier scopes remain in exported history. Existing jobs and answers are reused. Failed/cancelled/unsupported jobs stay explicit blockers and are handled individually in Work; the coordinator cannot bypass their authority checks.
6. **Drafts prepared — review required** means only these uploaded-source jobs have prepared current drafts without known blockers. Review the drafts and define/sign the separate supported close scope. Manual drafts, carried schedules, external ledger checks and missing documents are not inferred to be included.

This first close-level coordinator preserves existing per-document interpretation and request/reply routing. Coverage requirements now support consolidated client requests and scoped replies through the same durable jobs; see [coverage and attachments](coverage-requests.md). It does not infer complete account coverage, bulk-cancel work, or autonomously approve accounting methods. One consolidated visual question list is not a consolidated delivery authorization. Delivery still requires its own explicit authorization.

## Ledger coverage

Capture period evidence from the QuickBooks panel to see account-level coverage proposals and report row references above the upload-job progress. Coverage resolves automatically after the accountant binds the complete required job set and all its current outputs are approved. Uploading a document or completing an unapproved draft does not satisfy an account. Review scope and exclusions explicitly. New ledger evidence changes the run digest and supersedes source-dependent approvals; see [the period flow](quickbooks-onboarding.md#period-ledger-evidence-and-coverage-planning).
